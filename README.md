# Index Lens

김건호의 논문 **「MariaDB 데이터 규모와 인덱스 구성에 따른 조회 지연시간 비교」**의 실제 측정 결과를 탐색하는 정적 웹 애플리케이션입니다.

첫 화면의 **논문 원문 보기**를 누르면 앱의 근거가 된 PDF를 로그인 없이 확인할 수 있습니다.

## 누구를 어떻게 돕는가

대용량 MariaDB 조회를 설계하는 개발자가 데이터 규모를 선택하면, 논문의 실제 측정값으로 세 인덱스 구성을 비교하고 선택 근거를 확인할 수 있습니다.

## 사용자가 할 일

1. 논문에서 측정한 데이터 규모를 선택합니다.
2. 인덱스 없음·단일 인덱스·복합 인덱스의 중앙값 지연시간을 비교합니다.
3. 각 조건에서 실제로 선택된 key, 접근 방식, 읽은 행 수를 확인합니다.

직접 행 수를 입력하면 가장 가까운 측정 규모를 안내합니다. 측정 범위를 벗어나거나 숫자가 아닌 값을 입력해도 앱은 멈추지 않고 입력 기준을 보여 줍니다.

## 실행 방법

별도 설치나 빌드가 필요하지 않습니다.

1. 이 폴더에서 정적 HTTP 서버를 실행합니다.
2. 브라우저에서 서버 주소를 엽니다.
3. `index.html`이 표시되면 바로 사용할 수 있습니다.

Python이 설치된 환경의 예:

```bash
python -m http.server 4174
```

그다음 `http://localhost:4174`를 엽니다.

## GitHub Pages 배포

이 프로젝트에는 `master` 브랜치에 푸시될 때 정적 파일 전체를 배포하는 `.github/workflows/pages.yml`이 포함되어 있습니다.

1. GitHub에 `mariadb-index-advisor` 저장소를 만듭니다.
2. 이 폴더의 파일을 `master` 브랜치에 푸시합니다.
3. 저장소 `Settings → Pages`에서 Source를 `GitHub Actions`로 지정합니다.
4. Actions의 `Deploy static site to Pages` 실행이 성공한 뒤 새 시크릿 창에서 공개 URL을 확인합니다.

저장소 이름을 그대로 사용하면 예상 주소는 `https://prjsghq7.github.io/mariadb-index-advisor/`입니다. 실제 배포 완료 전에는 공개 URL로 간주하지 않습니다.

## 데이터 범위

- 데이터 규모: 1,000 / 10,000 / 100,000 / 1,000,000행
- 인덱스 조건: 없음 / `INDEX(department)` / `INDEX(department, age)`
- 조회 조건: `department = 'DEV' AND age = 30`
- 선택도: 모든 규모에서 1%
- 대표값: 조건별 10회 측정의 중앙값

앱의 수치는 논문 표 3~5의 결과를 그대로 사용합니다. 이는 MariaDB 11.4.5, 한 대의 로컬 PC, 해당 SELECT와 반복 실행 후 상태에서 얻은 측정값이며 다른 운영 환경의 성능을 예측하지 않습니다.

## 구성

- `index.html`: 화면 구조와 설명
- `styles.css`: 반응형 디자인과 인터랙션 스타일
- `app.js`: 논문 측정 데이터, 비교 계산, 입력 검증
- `documents/MariaDB_인덱스_조회_성능_연구_김건호.pdf`: 앱의 근거 논문 원문
- `.github/workflows/pages.yml`: GitHub Pages 자동 배포 설정

실제 개인정보, API 키, 토큰 또는 외부 서비스 의존성은 포함하지 않습니다.
